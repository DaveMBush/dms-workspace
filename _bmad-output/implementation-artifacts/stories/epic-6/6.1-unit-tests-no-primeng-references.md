# Story 6.1: Unit tests asserting no PrimeNg references remain

Status: ready-for-dev

## Story

As a developer,
I want a red-phase test that fails while `@primeng/themes` and `primeng` are still declared in the dms-material dependency set (or referenced anywhere in source),
So that Story 6.2 has an executable contract proving PrimeNg is fully removed before the packages are deleted.

## Acceptance Criteria

1. A new test asserts neither `@primeng/themes` nor `primeng` appears as a key in the workspace-root `package.json` (dms-material has no per-app manifest — deps are root-hoisted) under either `dependencies` or `devDependencies`.
2. The same (or sibling) test scans `apps/dms-material/src/**/*.{ts,scss}` and asserts no file imports from `primeng`, `@primeng/themes`, or any `@primeng/*` specifier — i.e., zero source references to the PrimeNg packages.
3. All new assertions in this story are marked `.skip()` (`it.skip`) in code so CI stays green while the packages are still declared; every pre-existing test remains unskipped and green.

## Tasks / Subtasks

- [ ] Task 1: Add red-phase tests for PrimeNg removal (AC: #1, #2)
  - [ ] 1.1 In a new spec under `apps/dms-material/src/` (e.g., `primeng-removal.spec.ts`), read the workspace-root `package.json` and assert neither `@primeng/themes` nor `primeng` is present in `dependencies` or `devDependencies`.
  - [ ] 1.2 Add a test that walks `apps/dms-material/src/**/*.{ts,scss}` (via the Vitest/Vite glob or a recursive read) and asserts no file contains an import/require of `primeng`, `@primeng/themes`, or any `@primeng/*` specifier.
- [ ] Task 2: Mark all new tests `.skip()` so CI stays green (AC: #3)
  - [ ] 2.1 Prefix each new `it(...)` with `.skip` (`it.skip`) and add a comment noting Story 6.2 removes the skips, confirms red, then deletes the packages until green.

## Dev Notes

- Red-phase TDD convention: this story writes failing tests marked `.skip()` in code (Vitest/Jest `it.skip`) so CI stays green; Story 6.2's FIRST task is to remove those skips, confirm they fail (red), then delete the packages until green. Both stories are `Status: ready-for-dev`.
- **Current state verified on disk:** as of this story's generation there are ZERO real PrimeNg references in dms-material source — no TS import and no SCSS `@import`/`@use` of `@primeng/themes`. The only trace is a stale comment at line 1 of `apps/dms-material/src/themes/_theme-variables.scss`: `// Theme color definitions matching PrimeNG Aura theme`. So AC #2 (no source references) already passes; the genuinely-red assertion is AC #1, because both packages are still declared in the workspace-root `package.json` under `dependencies` (`@primeng/themes: ^21.0.4`, `primeng: ^21.1.1`).
- The test must read the real `package.json` (not a fixture) so it actually fails while the deps exist and passes once Story 6.2 deletes them — that is what makes this a valid red→green pair rather than a tautology.
- Do NOT assert on `node_modules` or lockfile contents; scope to `package.json` keys + source-tree imports only, so the test stays fast and deterministic.
