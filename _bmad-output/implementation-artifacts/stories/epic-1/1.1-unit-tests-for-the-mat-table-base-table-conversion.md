# Story 1.1: Unit tests for the mat-table base-table conversion

Status: ready-for-dev

## Story

As a developer,
I want a red-phase unit-test scaffold asserting `dms-base-table` renders with standard Angular Material `mat-table` markup,
So that the implementation story has a defined, executable contract to make pass.

## Acceptance Criteria

1. `base-table.component.spec.ts` asserts the rendered DOM contains `<mat-table>`, `<ng-container matColumnDef>`, `<mat-header-cell *matHeaderCellDef>`, and `<mat-cell *matCellDef>` markup.
2. The spec asserts the old two-region DIV markers (`.dms-table-header`, `.dms-outer-scroller`, `.dms-col-spacer`) are no longer part of the rendered header/body split.
3. The spec asserts sorting behavior is preserved: clicking a sortable header emits `sortChange` with the expected direction cycle (asc → desc → off) and `aria-sort` is set on the header cell.
4. The spec asserts selection behavior is preserved: the select-all and per-row `mat-checkbox` toggle `selectionChange` through the `SelectionModel`.
5. The spec asserts `renderedRangeChange` still emits with a 100ms debounce (fake timers) and default cell rendering (currency/number/date/text types) is unchanged.
6. Every newly written or rewritten test in this story is marked `.skip()` in code (`it.skip`) so the dms-material Vitest suite runs green BEFORE Story 1.2 exists — red-phase by skip, not by failure. Existing passing tests that are kept (sort/selection/debounce/cell-rendering guards) stay unskipped and must remain green.
7. The suite runs green under the dms-material Vitest configuration immediately after this story (all new assertions skipped), and Story 1.2's first task is to remove the `.skip()` markers, confirm AC #1–#5 go red, then implement until they pass.

## Tasks / Subtasks

- [ ] Task 1 (AC: #1, #2): Rewrite markup assertions in `apps/dms-material/src/app/shared/components/base-table/base-table.component.spec.ts`.
  - [ ] 1.1 Replace `.dms-table-header` / `.dms-outer-scroller` / `.dms-col-spacer` selector assertions with `mat-table`, `matColumnDef`, `mat-header-cell`, `mat-cell` assertions.
  - [ ] 1.2 Update the `mockViewport()` CdkVirtualScrollViewport harness (mock `renderedRangeStream` as a `Subject<ListRange>`) to fit the new template if the virtual-scroll element moves.
  - [ ] 1.3 Assert the two-region DIV classes are absent from the rendered output.
- [ ] Task 2 (AC: #3): Rewrite sort tests for the new mechanism.
  - [ ] 2.1 Header-click test: cycle asc → desc → off, assert `sortChange` output payload each step.
  - [ ] 2.2 Assert `aria-sort` attribute on the active `mat-header-cell`.
- [ ] Task 3 (AC: #4): Rewrite selection tests.
  - [ ] 3.1 Select-all checkbox toggles full selection and emits `selectionChange`.
  - [ ] 3.2 Per-row checkbox toggles single-row selection and emits `selectionChange`.
- [ ] Task 4 (AC: #5): Keep/restore debounce and cell-rendering tests.
  - [ ] 4.1 `vi.useFakeTimers()` — advance 100ms — assert `renderedRangeChange` fires with the viewport `ListRange`.
  - [ ] 4.2 Assert default cell rendering per `ColumnDef.type` (currency, number, date, text) is unchanged.
- [ ] Task 5 (AC: #6): Mark every newly written or rewritten test `.skip()` in code (`it.skip`).
  - [ ] 5.1 Apply `it.skip` to all tests from Tasks 1–3 that assert the NEW mat-table markup/behavior (they are red until Story 1.2 lands).
  - [ ] 5.2 Leave existing passing guard tests (sort, selection, debounce, cell rendering) unskipped — they must stay green now and after Story 1.2.
  - [ ] 5.3 Run the dms-material unit test suite and confirm it is fully green with the new tests skipped. Do NOT weaken or delete any assertion to achieve this — skip markers only.
