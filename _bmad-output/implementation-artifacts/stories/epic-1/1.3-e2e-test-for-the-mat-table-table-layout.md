# Story 1.3: e2e test for the mat-table table layout

Status: ready-for-dev

## Story

As a user,
I want the data tables to render and interact correctly after the `mat-table` conversion,
so that I can sort, select, scroll, and inline-edit in every table surface without regressions — and so that the obsolete two-region-layout e2e suites are retired rather than left failing.

## Acceptance Criteria

1. A new spec `apps/dms-material-e2e/src/base-table-mat-table.spec.ts` asserts, on a seeded consumer screen (open-positions or global-universe), that rows render with Material table markup: the table is `<table mat-table>` (or `[role="table"]`), body rows are `tr[role="row"].dms-body-row`, and each row's computed height equals the 57px default (`rowHeight`).
2. The same spec asserts sorting: clicking a sortable header cell (`.dms-header-cell[data-column=X]`) toggles sort direction, and when a rank is active the `span.sort-rank-indicator[data-testid="sort-rank"]` badge appears in that header cell with the expected superscript + arrow text.
3. The same spec asserts selection: the select-all checkbox (when `multiSelect`) and per-row checkboxes toggle row `.selected` state, and the preserved `[data-column]` body cells remain addressable.
4. The same spec asserts virtual scroll: scrolling the table renders additional rows (`cdk-virtual-scroll-viewport` present) without breaking layout — no horizontal scrollbar on the body region and header stays pinned above the viewport while scrolling.
5. The two structurally-dead suites are retired (deleted): `apps/dms-material-e2e/src/base-table-two-region-regression.spec.ts` and `apps/dms-material-e2e/src/base-table-layout-regression.spec.ts`. Their invariants (header NOT sticky, `.dms-outer-scroller` owns vertical scroll, header/body width sync via mirrored scrollLeft, `.dms-col-spacer` math) no longer apply to a single standard mat-table.
6. The smooth-scroll specs that feed `.dms-outer-scroller` as the scroll container are updated to target the new scroller (`cdk-virtual-scroll-viewport`) so they pass: `universe-smooth-scroll.spec.ts`, `screener-smooth-scroll.spec.ts`, `open-positions-smooth-scroll.spec.ts`, `div-deposits-smooth-scroll.spec.ts` (and any other spec passing `.dms-outer-scroller`).
7. The shared helper `apps/dms-material-e2e/src/helpers/assert-sticky-header-invariant.helper.ts` is retired or repurposed: its default header selector and the "header must NOT be position:sticky" geometric invariants are two-region-specific. If any surviving spec still needs a sticky-header check, it is rewritten against mat-table's native sticky `th`; otherwise the helper file is deleted along with its callers.
8. The full e2e run (`pnpm nx run dms-material-e2e:e2e`) passes for the table-related specs: the new spec plus all consumer specs that rely on the preserved `.dms-header-cell[data-column]` / `.dms-body-row[role=row]` / `.dms-body-cell[data-column]` selectors (which Story 1.2 kept) still resolve and pass without edits.

## Dev Notes

- Cites AD-1, AD-2, AD-4 and FR-2/FR-3/FR-4/FR-5/FR-7 (same as Epic 1). This is the e2e half of the triple for the mat-table conversion; it depends on Story 1.2 being implemented first.
- **Why this story exists:** the conversion removes the two-region layout that ~64 e2e spec files and several helpers reference. Story 1.2 deliberately preserved the load-bearing selectors (`.dms-header-cell[data-column]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column]`) so most consumer specs survive untouched. This story handles the remainder: retire what is structurally dead, retarget the scroll container, and add a fresh spec that proves the new mat-table layout works end-to-end.
- **Verbatim pointer from the Epic prose** (the markup this e2e must now see):

``` html
<mat-table [dataSource]="dataSource">
  <ng-container matColumnDef="username">
    <mat-header-cell *matHeaderCellDef> User name </mat-header-cell>
    <mat-cell *matCellDef="let row"> {{row.username}} </mat-cell>
  </ng-container>
  ...
  <mat-header-row *matHeaderRowDef="['username', 'age', 'title']"></mat-header-row>
  <mat-row *matRowDef="let row; columns: ['username', 'age', 'title']"></mat-row>
</mat-table>
```

- **e2e runtime:** `apps/dms-material-e2e/playwright.config.ts` uses `nxE2EPreset`, `workers: 1`, serial, shared SQLite. It boots (1) the Express API server on port 3001 (`DATABASE_URL=file:./test-database.db`) and (2) the Angular dev server on port 4301 with a proxy; `baseURL = http://localhost:4301`. Run via `pnpm nx run dms-material-e2e:e2e` (or the `e2e:dms-material:*` npm scripts). Git worktrees get a +100..+299 port offset.
- **Judgment call — scope of selector migration.** Only the structurally-dead suites and the scroll-container/helper references are touched here. The ~50 consumer specs that target preserved selectors (`.dms-header-cell[data-column=X]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column=X]`) are expected to pass unchanged because Story 1.2 kept those class names + `data-column` on the new `th`/`tr`/`td`. If a broader selector cleanup is later desired (e.g. dropping the legacy class aliases entirely), that is a separate follow-up story — it is out of scope here to keep this single-session-sized.
- **Judgment call — which suites are "dead."** `base-table-two-region-regression.spec.ts` and `base-table-layout-regression.spec.ts` assert invariants that only exist because the header was a separate region (header not sticky, `.dms-outer-scroller` owns vertical scroll, mirrored horizontal scrollLeft, `.dms-col-spacer` width math). A single standard mat-table has native sticky headers and one scroller, so those invariants are meaningless — delete both files rather than rewrite them.
- The `assert-sticky-header-invariant.helper.ts` default header selector is `.dms-header-cell[role="columnheader"]`; that class survives (Story 1.2), but the helper's core invariant ("computed position must NOT be sticky") is inverted for mat-table, so it cannot be reused as-is — retire or rewrite per Task 4.
