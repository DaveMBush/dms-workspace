# Story 1.2: Convert dms-base-table to Angular Material mat-table

Status: ready-for-dev

## Story

As a developer,
I want `dms-base-table` rebuilt on the standard Angular Material `<table mat-table>` / `matColumnDef` / `mat-header-row` / `mat-row` syntax,
so that the table layout is standard, the sticky-header scroll bugs disappear, and the bespoke header/table separation (two-region DIV layout) is removed.

## Acceptance Criteria

1. The template renders a single `<table mat-table [dataSource]="dataSource()" [trackBy]="trackByFn">` containing `ng-container [matColumnDef]`, `th mat-header-cell *matHeaderCellDef`, `td mat-cell *matCellDef="let row"`, and `tr mat-header-row *matHeaderRowDef` / `tr mat-row *matRowDef`. The old two-region DIV structure (`.dms-table-shell`, `.dms-table-header-viewport`, `.dms-table-header`, `.dms-outer-scroller`, `.dms-table-scroll-container`) is gone; header and body live in one table.
2. The public API of `BaseTableComponent<T>` is unchanged so consumers compile without edits: inputs `data`, `columns`, `tableLabel`, `rowHeight` (default 57), `bufferSize` (default 10), `selectable`, `multiSelect`, `loading`, `sortColumns`, `contextId`; outputs `sortChange`, `rowClick`, `selectionChange`, `renderedRangeChange`.
3. Sorting is preserved via the EXISTING mechanism — the `sortColumns` input, `onHeaderClick(column)`, and the computed `sortRankMap()` (superscript rank + ↑/↓ arrow). Do NOT swap in Angular Material `MatSort`; the current component has no `MatSortModule` import. The active header cell keeps `[attr.aria-sort]` via `getAriaSort(column)` and renders the `<span class="sort-rank-indicator" data-testid="sort-rank">` badge when a rank is present.
4. Selection is preserved: select-all `mat-checkbox` (only when `multiSelect()`) bound to `isAllSelected()` / indeterminate, per-row `mat-checkbox` bound to `selection.isSelected(row)`, both driving the existing `SelectionModel<T>` and emitting `selectionChange`.
5. Virtual scroll is preserved by wrapping the table body in `<cdk-virtual-scroll-viewport #viewport [itemSize]="rowHeight()" [minBufferPx]="rowHeight()*bufferSize()" [maxBufferPx]="rowHeight()*bufferSize()*2">` (the same pattern used at commit 36ee7e7). `renderedRangeChange` still emits the viewport `ListRange`, debounced 100ms, in `ngAfterViewInit`.
6. Default cell rendering is unchanged: the `#defaultCell` `<ng-template>` with `@switch (column.type)` for `currency` / `date : 'shortDate'` / `number` / default text, projected via `[ngTemplateOutlet]="cellTemplate || defaultCell"` with context `{ $implicit: row, column, index }`.
7. Row semantics are preserved on the `tr mat-row`: `[class.selected]`, `[class.expired]`, `[ngClass]="gainLossClassMap$(row)"`, `[attr.data-is-cef]`, `[attr.data-has-position]`, `(click)="onRowClick(row)"`, and keyboard Enter/Space activation.
8. e2e selector compatibility is preserved: header cells keep `class="dms-header-cell"` + `[attr.data-column]="column.field"`, body rows keep `class="dms-body-row"`, and body cells keep `class="dms-body-cell"` + `[attr.data-column]="column.field"`. The native `role="row"` / `role="cell"` / `role="columnheader"` that Material table emits are retained. This keeps the ~50 consumer e2e specs (which target `.dms-header-cell[data-column=X]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column=X]`) resolving without edits.
9. The now-dead header/body scroll-sync is removed: delete the `headerScrollViewport` and `outerScroller` `viewChild` refs, remove the `bindHeaderInteractions(...)` call from `ngAfterViewInit`, and delete `base-table-scroll.utils.ts` + `base-table-scroll.utils.spec.ts` (they exist only to mirror body scrollLeft into a separate header region).
10. Story 1.1's unit tests pass: rendered DOM contains `<mat-table>` / `matColumnDef` / `mat-header-cell` / `mat-cell`, and the old two-region markers are absent; sort/selection/debounce/cell-rendering behavior is unchanged.

- **Verbatim target syntax from the Epic prose** (the desired end-state markup):

``` html
<mat-table [dataSource]="dataSource">
  <!-- User name Definition -->
  <ng-container matColumnDef="username">
    <mat-header-cell *matHeaderCellDef> User name </mat-header-cell>
    <mat-cell *matCellDef="let row"> {{row.username}} </mat-cell>
  </ng-container>

  <!-- Age Definition -->
  <ng-container matColumnDef="age">
    <mat-header-cell *matHeaderCellDef> Age </mat-header-cell>
    <mat-cell *matCellDef="let row"> {{row.age}} </mat-cell>
  </ng-container>

  <!-- Title Definition -->
  <ng-container matColumnDef="title">
    <mat-header-cell *matHeaderCellDef> Title </mat-header-cell>
    <mat-cell *matCellDef="let row"> {{row.title}} </mat-cell>
  </ng-container>

  <!-- Header and Row Declarations -->
  <mat-header-row *matHeaderRowDef="['username', 'age', 'title']"></mat-header-row>
  <mat-row *matRowDef="let row; columns: ['username', 'age', 'title']"></mat-row>
</mat-table>
```

- **Judgment call — preserve the existing sort mechanism, do not adopt MatSort.** The Epic breakdown (epics.md) phrases this as "multi-column MatSort with rank badges," but the current `BaseTableComponent` does NOT import or use Angular Material `MatSort`; it uses a custom `sortColumns` input + `onHeaderClick()` + computed `sortRankMap()`. Swapping to `MatSort` would change the public API and break consumers. This story keeps the existing mechanism and only changes the DOM structure. If MatSort is genuinely wanted, that is a separate follow-up story.
- **Judgment call — preserve e2e selectors.** ~50 consumer e2e specs target `.dms-header-cell[data-column=X]`, `.dms-body-row[role=row]`, and `.dms-body-cell[data-column=X]`. To avoid a 64-file e2e migration, this story carries those class names + `data-column` attributes onto the new `th`/`tr`/`td` elements (AC #8). Only the structurally-dead two-region suites are retired — that is Story 1.3's scope, not this one.
- The original commit used `<table mat-table>` inside a `cdk-virtual-scroll-viewport`; that exact nesting is proven in this codebase's history and is what AC #5 restores.
- `base-table.component.ts` is excluded from the 100% coverage gate, so coverage drift does not block CI — but Story 1.1's behavioral tests are the contract to keep green.
