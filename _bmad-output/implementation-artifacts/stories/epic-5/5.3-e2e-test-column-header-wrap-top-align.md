# Story 5.3: E2E test for column header wrap + top alignment

Status: review

## Story

As a user (Dave),
I want an end-to-end proof that every table's column headers show their full text — wrapping onto multiple lines instead of being clipped — and start at the top of the header cell, across different screen sizes,
So that I can trust no header information is hidden by styling in real use.

## Acceptance Criteria

1. A new Playwright spec opens a table view with long column headers (e.g., Open Positions or Universe) and asserts each rendered `.dms-header-cell` shows its full `column.header` text: the cell's scroll height equals its client height (no vertical clipping), no ellipsis is applied, and the computed style has `white-space` resolving to `normal`/unset (not `nowrap`) with `text-overflow` not `ellipsis`.
2. The same spec asserts a wrapped header cell's text starts at the top of the cell: the first line of header text sits at the top edge of the `.dms-header-cell` bounding box (computed `vertical-align: top`, or an equivalent top-alignment assertion via getBoundingClientRect).
3. The assertions hold across at least two viewport sizes (e.g., 1280px desktop and 768px tablet) — headers wrap rather than clip, and the table container does not gain horizontal overflow from the wrapping.
4. The existing e2e specs `open-positions.spec.ts` and `dividend-deposits-modal.spec.ts` pass unchanged alongside the new spec on chromium; no pre-existing test regresses.

## Dev Notes

- **Prerequisite:** Story 5.2 must be complete (clipping styles removed, unit tests green). Against unfixed code this spec will observe `white-space: nowrap` / `text-overflow: ellipsis` on `.dms-header-cell` and the full header text will not fit — that is the red signal.
- **Single shared component:** every table in the app renders through `dms-base-table`, so one e2e spec against a representative long-header view (Open Positions or Universe) covers all tables; do not write per-table specs.
- **Assert on the class, not the tag:** Material emits `role="columnheader"` via host bindings regardless of element type — locate header cells by `.dms-header-cell` and read computed styles / bounding boxes from there. The load-bearing contract is `.dms-header-cell[data-column]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column]`.
- **Body rows must stay single-line:** this story only verifies header cells; do not assert on body-cell truncation (that behavior is intentionally preserved by Story 5.2 so the fixed 57px row height and virtual-scroll itemSize remain stable).
- **e2e DB note:** run Playwright from workspace root (as the `@nx/playwright` executor does) so both server and helper hit `<root>/test-database.db`; regenerate with `node tools/create-test-db.js test-database.db` if seeding errors appear. The shared e2e SQLite DB accumulates rows across runs — kill orphaned servers + delete the DB for a clean run if count/filter assertions misbehave.
- **Reuse existing helpers:** follow the setup/teardown patterns already used in `apps/dms-material-e2e/src/open-positions.spec.ts` so the new spec stays consistent with the suite.
- Playwright for e2e; chromium project only is sufficient for this story.
