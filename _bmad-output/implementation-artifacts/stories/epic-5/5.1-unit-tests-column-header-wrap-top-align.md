# Story 5.1: Unit tests for column header wrap + top alignment

Status: done

## Story

As a developer,
I want a red-phase unit-test scaffold asserting that `dms-base-table` column headers wrap fully (no clipping) and align to the top of their cell,
So that Story 5.2 has a defined, executable contract to make pass when it removes the header text-clipping styles.

## Acceptance Criteria

1. A new unit test in `apps/dms-material/src/app/shared/components/base-table/base-table.component.spec.ts` renders `dms-base-table` with a column whose `header` is long enough to wrap at the configured column width, and asserts the rendered `.dms-header-cell` computed style does NOT clip: `white-space` resolves to `normal` (or is unset — not `nowrap`) and `text-overflow` is not `ellipsis`.
2. The same spec asserts a wrapped header cell's text starts at the top of the cell: the cell's vertical alignment is `top` (computed `vertical-align: top`, or an equivalent top-alignment assertion), so multi-line headers are not vertically centered or bottom-aligned.
3. A second unit test renders a short single-line header and asserts it still renders correctly (no regression to single-line headers) with the same non-clipping, top-aligned style.
4. All new assertions in this story are marked `.skip()` (`it.skip`) in code so CI stays green while the clipping bug still exists; every pre-existing test in `base-table.component.spec.ts` remains unskipped and green.

## Dev Notes

- Red-phase TDD convention: this story writes failing tests marked `.skip()` in code (Vitest/Jest `it.skip`) so CI stays green; Story 5.2's FIRST task is to remove those skips, confirm they fail (red), then implement until green. Both stories are `Status: ready-for-dev`.
- The clipping comes from the shared header-cell style in `apps/dms-material/src/app/shared/components/base-table/base-table.component.scss` `.dms-header-cell` block (lines 49–67): it currently sets `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`. That is the single source of clipping for every table that renders through `dms-base-table`, so the unit test targets this one component.
- The header cell markup lives in `apps/dms-material/src/app/shared/components/base-table/base-table.component.html` (the `<mat-header-cell *matHeaderCellDef class="dms-header-cell">` at lines 55–77). Material emits `role="columnheader"` via host bindings regardless of element type — assert on the `.dms-header-cell` class, not a native tag.
- The load-bearing table contract that must survive any change: `.dms-header-cell[data-column]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column]` (class + role + data-column, never the native element tag). Do not weaken these in the new tests.
- Testing standard: Angular component test harness (`TestBed`) with `NoopAnimationsModule`; assert computed styles via `getComputedStyle` on the rendered header cell element.
