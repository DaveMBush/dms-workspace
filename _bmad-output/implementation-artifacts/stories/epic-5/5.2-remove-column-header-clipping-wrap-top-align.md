# Story 5.2: Remove column header clipping; allow wrap + top alignment

Status: in-progress

## Story

As a user (Dave),
I want the column headers in every table to show their full text — wrapping onto multiple lines instead of being cut off — and to start at the top of the header cell,
So that no header information is hidden by `white-space: nowrap` / `text-overflow: ellipsis` styling.

## Acceptance Criteria

1. The shared `.dms-header-cell` style in `apps/dms-material/src/app/shared/components/base-table/base-table.component.scss` no longer clips text: it does not set `white-space: nowrap`, `text-overflow: ellipsis`, or `overflow: hidden`.
2. A wrapped header cell's text aligns to the top of the cell (computed `vertical-align: top`), so multi-line headers are not vertically centered or bottom-aligned.
3. The body-cell truncation is preserved unchanged: `.dms-body-cell` still sets `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`, and data rows keep their single-line, 57px behavior (no regression to row height or virtual-scroll itemSize).
4. Story 5.1's red-phase unit assertions are unskipped and pass under `nx test dms-material`; no pre-existing test in `base-table.component.spec.ts` regresses.

## Dev Notes

- Red-phase TDD convention: Story 5.1 wrote failing tests marked `.skip()` so CI stayed green; this story's FIRST task is to remove those skips, confirm they fail (red), then implement until green. Both stories are `Status: ready-for-dev`.
- The single source of header clipping for every table that renders through `dms-base-table` is the `.dms-header-cell` block in `apps/dms-material/src/app/shared/components/base-table/base-table.component.scss` (lines 49–67). Changing this one block fixes all tables at once — do not add per-table overrides.
- Do NOT touch `.dms-body-cell` (lines 112–117): data rows must stay single-line and truncated so the fixed `--mat-table-row-item-container-height: 57px` row height (line 10) and CDK virtual-scroll itemSize remain stable. Only header cells change.
- Header cell markup is in `apps/dms-material/src/app/shared/components/base-table/base-table.component.html` (`<mat-header-cell *matHeaderCellDef class="dms-header-cell">`, lines 55–77). Material emits `role="columnheader"` via host bindings; assert on the `.dms-header-cell` class, not a native tag.
- Load-bearing table contract that must survive: `.dms-header-cell[data-column]`, `.dms-body-row[role=row]`, `.dms-body-cell[data-column]` (class + role + data-column, never the native element tag). Do not weaken these.
- The prose also asks to "review all tables in the application" and "test across different screen sizes and browsers." Because every table renders through this one shared component, fixing the single `.dms-header-cell` block covers all tables; the cross-screen/browser verification is owned by Story 5.3 (e2e).
- Testing standard: Angular component test harness (`TestBed`) with `NoopAnimationsModule`; assert computed styles via `getComputedStyle` on the rendered header cell element.
