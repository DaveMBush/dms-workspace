# Story 3.1: Unit tests for the div-based mat-table conversion

Status: in-progress

## Story

As a developer,
I want red-phase unit-test assertions that `BaseTableComponent` renders Material's **div-based** `<mat-table>` markup (no native `<table>`/`<th>`/`<td>`/`<tr>` elements) while preserving the load-bearing `.dms-*` classes, ARIA roles, and `data-column` attributes,
So that Story 3.2 has a defined contract to make pass when it converts the template from Epic 1's `<table mat-table>` element form to the div-based custom-element syntax.

## Acceptance Criteria

1. The spec file `apps/dms-material/src/app/shared/components/base-table/base-table-mat-table.spec.ts` gains assertions that, after `fixture.detectChanges()`, the rendered table is a **div-based** Material table: an element matching `mat-table[role="table"]` (or `.mat-mdc-table`) exists inside the `cdk-virtual-scroll-viewport`.
2. The same spec asserts the native table elements are GONE from the component DOM: `el.querySelector('table')`, `el.querySelector('th')`, `el.querySelector('td')`, and `el.querySelector('tr')` all return `null` (the div-based mat-table renders `<div>`s, not `<table>`/`<th>`/`<td>`/`<tr>`).
3. The same spec asserts the load-bearing selectors SURVIVE the conversion: header cells match `.dms-header-cell[role="columnheader"][data-column]`, body rows match `.dms-body-row[role="row"]`, and body cells match `.dms-body-cell[data-column]` — i.e. the class + ARIA-role + `data-column` contract that ~50 consumer e2e specs depend on is intact on div-based elements.
4. The same spec asserts sticky-header behavior: the column-header row (`.dms-column-header-row`) computes to a sticky position (`position: sticky`, or Material's equivalent host binding) so it stays pinned above the `cdk-virtual-scroll-viewport` body — the benefit of moving off the native `<table>` element form (Epic 1 already pins via Material `[sticky]` in a single table; no two-region layout remains).
5. Every div-based structure assertion that depends on Story 3.2 (AC #1–#4: div-based markup present, native elements absent, roles preserved on divs, sticky header) is marked `.skip()` in code (`it.skip`) so CI stays green BEFORE the conversion lands — red-phase by skip, not by failure. In addition, this story RETIRES the Epic 1 assertions that pin the `<table>` structure we are converting away from: (a) the test asserting native elements EXIST (`table[mat-table]`, `th[mat-header-cell]`, `td[mat-cell]`, `tr[mat-row]` non-null) is REMOVED — its div-based inverse ("no native table elements; div mat-table present") is already added as a skipped red-phase assertion in AC #1–#2; and (b) the behavioral assertions (sort emits, aria-sort updates, checkbox renders) have their selectors ADAPTED to be structure-agnostic — `.dms-header-cell[data-column=...]`, `.dms-body-row[role="row"]`, `cdk-virtual-scroll-viewport .mat-mdc-table` (class + role/data-column, no native element tag) — so they pass against BOTH the current `<table mat-table>` and the future div-based template and stay UNskipped/green.
6. The spec file runs green under `nx test dms-material` immediately after this story (red-phase tests skipped), and Story 3.2's first task is to remove the `.skip()` markers, confirm they fail against the current `<table mat-table>` template, then implement until they pass.

## Dev Notes

- Red-phase TDD: this story is ordered before Story 3.2. The div-based assertions (AC #1–#4) are marked `it.skip` in code so CI stays green while the template still renders Epic 1's `<table mat-table>` element form; the existing class/role/data-column guards stay unskipped and green. Story 3.2's first task removes the skip markers, confirms red, then makes them pass.
- Cites AD-4 (single standard `mat-table` with native sticky headers replaces the two-region layout) from ARCHITECTURE-SPINE, and FR-2/FR-3/FR-4/FR-5/FR-7 (same as Epic 1). This is the unit-test half of the triple for the div-based conversion; it depends on Story 1.2's `<table mat-table>` being in place first.
- **Why div-based, not element form:** Epic 1 converted to `<table mat-table>` (native table element + Material directive) with native sticky headers — no two-region layout remains today. The Epic prose specifies the div-based custom-element syntax (`<mat-table>`, `<mat-header-cell>`, `<mat-cell>`, `<mat-row>`) so Material renders `<div>`s instead of a native table, removing the native-table sticky-header quirks and letting the header be natively sticky inside a single standard mat-table.
- **Verified against installed Angular Material 22.1.4** (`node_modules/@angular/material/fesm2022/table.mjs`): the directive selectors are `mat-table, table[mat-table]`, `mat-header-cell, th[mat-header-cell]`, `mat-cell, td[mat-cell]`, `mat-row, tr[mat-row]`, `mat-header-row, tr[mat-header-row]`. So both element and attribute forms are valid in this version — the div-based form is supported.
- **Verified ARIA roles:** Material emits `role="row"` (rows) and `role="columnheader"` (header cells) via host bindings regardless of whether the host is a `<div>` or a native element. This is why the ~50 consumer e2e specs that target `.dms-body-row[role="row"]` / `.dms-header-cell[role="columnheader"]` survive the conversion untouched — they do not depend on the element being a `<table>`.
- The existing spec `base-table-mat-table.spec.ts` (created by Epic 1's Story 1.2) currently asserts the NATIVE structure: `el.querySelector('table[mat-table]')`, `th[mat-header-cell]`, `td[mat-cell]`, `tr[mat-row]` are all non-null, it counts rows via `querySelectorAll('tr[mat-row]')`, and its behavioral tests (sort emits, aria-sort updates, checkbox renders) locate elements by native tag (`th[data-column=...]`, `td input[type="checkbox"]`). This story does NOT leave those in place for Story 3.2 to clean up: Task 5 REMOVES the "native elements exist" markup test (its div-based inverse is already added as a skipped red-phase assertion) and ADAPTS the behavioral selectors to structure-agnostic class/role/data-column form so they pass against both templates. Only the new div-based STRUCTURE assertions are left `it.skip` for Story 3.2 to unskip.
- Vitest is the workspace test framework; dms-material unit tests run via `nx test dms-material`.
