# Story 3.2: Convert DMS BaseTable to div-based mat-table

Status: in-progress

## Story

As a developer,
I want `BaseTableComponent`'s template converted from Epic 1's `<table mat-table>` element form (native `<table>`/`<th>`/`<td>`/`<tr>`) to Material's **div-based** custom-element syntax (`<mat-table>`, `<mat-header-cell>`, `<mat-cell>`, `<mat-row>`),
So that the table renders as a single standard `mat-table` of `<div>`s with natively sticky headers — moving off the native `<table>` element form and its sticky-header quirks (Epic 1 already pins via Material `[sticky]`; no two-region layout remains) — while every load-bearing `.dms-*` class, ARIA role, `data-column` attribute, and event binding is preserved so existing unit tests and ~50 consumer e2e specs keep passing.

## Acceptance Criteria

1. The template `apps/dms-material/src/app/shared/components/base-table/base-table.component.html` uses div-based Material syntax: the table container is `<mat-table>` (not `<table mat-table>`), header cells are `<mat-header-cell>`, body cells are `<mat-cell>`, and rows are `<mat-row>` / `<mat-header-row>` — no native `<table>`, `<th>`, `<td>`, or `<tr>` elements remain in the template.
2. Every attribute, binding, class, and event on the converted elements is preserved exactly: `[dataSource]`, `[trackBy]`, `[attr.aria-label]` on the table; `class="dms-header-cell"`, `[class.dms-header-cell--sortable]`, `[attr.data-column]`, `[attr.tabindex]`, `[style.width.px]`, `[attr.aria-sort]`, `[matTooltip]`, and `(click)`/`(keydown.enter)`/`(keydown.space)` on header cells; `class="dms-body-cell"`, `[style.width.px]`, `[attr.data-column]` on body cells; the select/filter column defs, the filter row (`class="dms-filter-row"`), the column-header row (`class="dms-column-header-row"` with `sticky: true`), and the body rows (`class="dms-body-row"`, `[class.selected]`, `[class.expired]`, `[ngClass]`, `[attr.data-is-cef]`, `[attr.data-has-position]`, `(click)`) all survive unchanged.
3. The ARIA roles that Material emits via host bindings are intact on the div-based elements: header cells carry `role="columnheader"`, rows carry `role="row"` — so `.dms-header-cell[role="columnheader"]` and `.dms-body-row[role="row"]` still resolve (verified against installed Angular Material 22.1.4, which emits these roles regardless of host element type).
4. The SCSS is updated for the div-based table: the native-element selector `.dms-table-body table.mat-mdc-table { width: 100% }` becomes a selector that matches the `<mat-table>` element (e.g. `.dms-table-body mat-table.mat-mdc-table`), and any residual two-region / manual `position: sticky` header CSS left over from before Epic 1 is removed — Material's native sticky headers (`sticky: true` on the row defs) now own pinning.
5. The unit spec `base-table-mat-table.spec.ts` is fully div-based: Story 3.1 already removed the Epic 1 "native elements exist" markup test and adapted every behavioral selector to structure-agnostic class/role/data-column form (so no native-tag assertions remain in this story), and this story unskips Story 3.1's red-phase div-based STRUCTURE assertions (`it.skip` → `it`) — all green under `nx test dms-material`.
6. The component builds cleanly: `nx build dms-material` (or the project's type-check/build target) passes with no template or SCSS errors, and the existing class/role/data-column unit assertions that were already green against Epic 1 remain green.

## Dev Notes

- Cites AD-4 (single standard `mat-table` with native sticky headers replaces the two-region layout) from ARCHITECTURE-SPINE, and FR-2/FR-3/FR-4/FR-5/FR-7 (same as Epic 1). This is the implementation half of the triple; it depends on Story 3.1's red-phase tests being in place first.
- **Spec cleanup is split across the two stories.** Story 3.1 already REMOVED the Epic 1 "native elements exist" markup test and ADAPTED every behavioral selector (sort, aria-sort, checkbox) to structure-agnostic class/role/data-column form — so by the time this story runs, no native-tag assertions remain in `base-table-mat-table.spec.ts`. This story's spec work is: Task 0 unskips Story 3.1's red-phase div-based STRUCTURE assertions (confirming red), and Task 3 verifies they now pass plus greps that nothing native-tag remains. Do not re-do the retire/adapt here; if a stray native-tag selector surfaces, adapt it per Task 3.2.
- **Verified against installed Angular Material 22.1.4** (`node_modules/@angular/material/fesm2022/table.mjs`): directive selectors are `mat-table, table[mat-table]`, `mat-header-cell, th[mat-header-cell]`, `mat-cell, td[mat-cell]`, `mat-row, tr[mat-row]`, `mat-header-row, tr[mat-header-row]`. Both element and attribute forms are valid in this version — the div-based form is supported.
- **Verified ARIA roles:** Material emits `role="row"` (rows) and `role="columnheader"` (header cells) via host bindings regardless of whether the host is a `<div>` or a native element. This is why the ~50 consumer e2e specs that target `.dms-body-row[role="row"]` / `.dms-header-cell[role="columnheader"]` survive this conversion untouched — they do not depend on the element being a `<table>`.
- **Why div-based, not element form:** Epic 1 converted to `<table mat-table>` (native table element + Material directive) and kept native sticky headers. The Epic prose specifies the div-based custom-element syntax so Material renders `<div>`s — this removes the native-table sticky-header quirks that motivated the original two-region layout, and lets the header be natively sticky inside a single standard mat-table.
- **Preservation is the contract.** The ~50 consumer e2e specs (and the surviving unit assertions) target `.dms-header-cell[data-column=X]`, `.dms-body-row[role="row"]`, `.dms-body-cell[data-column=X]` — class + ARIA-role + `data-column`, never the native element tag. As long as Task 1 keeps every class, role (implicit via Material), and `data-column` on the new div-based elements, those specs pass without edits. Do not rename or drop any `.dms-*` class in this story; a broader selector cleanup is a separate follow-up.
- **Sticky headers:** stickiness comes from Material's `sticky: true` on the filter-row and column-header-row defs (template lines 119/127), which are preserved by Task 1.4. There is no separate `position: sticky` CSS in this component today; if any residual two-region sticky CSS exists, remove it per Task 2.2.
- **SCSS scoping:** the component uses ViewEncapsulation (default Emulated). If `.dms-table-body mat-table.mat-mdc-table` does not reach the Material-rendered inner divs, scope with `:host ::ng-deep` as needed — but prefer the direct element selector first and only add `::ng-deep` if a width/layout regression appears.
- Vitest is the workspace test framework; dms-material unit tests run via `nx test dms-material`.
