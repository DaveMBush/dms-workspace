## Findings

### 1. Virtual-scroll test never exercises virtualization — name overclaims
- **Location:** `apps/dms-material-e2e/src/base-table-div-mat-table.spec.ts:245-276` (test `'scrolling renders additional rows without breaking layout'`)
- **Severity:** Suggestion
- **Confidence:** high
- **Summary:** The test is named "renders additional rows" but its only post-scroll assertion is `expect(afterScrollRows).toBeGreaterThan(0)` — no baseline comparison, and the scroll is a no-op.
- **Failure scenario:** The e2e seed (`seed-universe-e2e-data.helper.ts` → `generateTestNames`) creates exactly 5 symbols; with CDK `itemSize=57` / `bufferSize=10`, all 5 rows (~285px) fit within viewport+buffer, so `vp.scrollTop += 300` clamps to ~0 movement and every row is already rendered up front. The test passes green whether or not virtualization works — it cannot distinguish a virtualized table from a fully-rendered one. AC #3's "scrolling renders additional rows" behavior is therefore unverified; the test only guards against total row loss / layout collapse (cell dimensions), which its name does not promise.
- **Fix direction:** Seed >10 rows so content overflows the viewport, then assert `afterScrollRows` reflects a re-rendered window (or at least that `scrollTop` actually changed before asserting). Alternatively rename to reflect what it truly checks ("rows remain rendered and cells keep non-zero dimensions after scroll").

### 2. Sticky-header test's "while scrolling" portion is vacuous
- **Location:** `apps/dms-material-e2e/src/base-table-div-mat-table.spec.ts:84-146` (test `'column header row stays pinned while scrolling the viewport'`; scroll at ~127-132, yDelta assertion at 140-145)
- **Severity:** Suggestion
- **Confidence:** high
- **Summary:** The computed-style check (`position:sticky` on the header row or its cells, lines 96-117) is a real assertion and passes. But the "stays pinned *while scrolling*" half relies on `vp.scrollTop = 500`, which clamps to ~0 with only 5 rows of content — so nothing actually scrolls and `yDelta` is exactly 0, making `expect(yDelta).toBeLessThan(50)` trivially true.
- **Failure scenario:** A regression where the header stops pinning during scroll (e.g., sticky offset misconfigured) would still pass this test in the default data setup, because the viewport never moves far enough to expose the defect. AC #2's dynamic "while scrolling" requirement is only partially covered by the static `position:sticky` check.
- **Fix direction:** Same root cause as Finding 1 — seed >10 rows so the content overflows and `scrollTop = 500` produces real movement, then assert the header row's Y stays stable relative to the scrolled body. Optionally assert `vp.scrollTop` actually changed before comparing boxes.

**Shared root cause (both findings):** the e2e universe seed yields only 5 rows, below CDK virtual-scroll `bufferSize=10`, so neither scrolling nor virtualization is genuinely exercised by AC #2/#3's dynamic assertions. Seeding >10 rows would make both tests meaningful with a single change to the test data setup (or a larger per-test seed).
