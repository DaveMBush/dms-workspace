# Story 4.1: Unit tests for add-position / add-div-deposit SmartNgRX state integrity (red-phase)

Status: in-progress

## Story

As a developer,
I want red-phase unit-test assertions that verify the parent `Account` entity's virtual-array field (`openTrades` / `divDeposits`) retains all three properties — `startIndex`, `indexes`, and `length` — after calling SmartNgRX's `SmartArray.add()`,
So that Story 4.2 has a defined contract to make pass when it fixes the state corruption in the add-position and add-div-deposit flows (the bug Dave reports: adding a position or dividend deposit then navigating away throws an exception).

## Acceptance Criteria

1. A spec asserts that after `AddPositionService.createDialogCloseHandler(...)` processes a valid dialog result, the parent `Account` entity's `openTrades` field in the SmartNgRX store has all three virtual-array properties defined: `startIndex` is a number (NOT `undefined`), `indexes` is an array whose last element equals the new trade's id, and `length` equals the prior length + 1.
2. A parallel assertion set verifies that after `DividendDepositsComponentService.addDivDeposit(...)` completes, the parent `Account` entity's `divDeposits` field has all three properties defined: `startIndex` is a number (NOT `undefined`), `indexes` contains the new deposit's id, and `length` equals prior + 1.
3. A navigation-simulation assertion verifies that after the add, re-evaluating the computed signal that reads the virtual array does NOT throw — i.e., iterating `trades[i]` (or `dividends[i]`) for every valid index returns either a row object or a string placeholder id and never throws on an undefined/missing `startIndex`.
4. All assertions in AC #1–#3 are marked `.skip()` (`it.skip`) so CI stays green BEFORE the fix lands — red-phase by skip, not by failure. The existing passing tests in `open-positions-component.service.spec.ts` and `dividend-deposits-component.service.spec.ts` remain unskipped and green.
5. The spec file runs green under `nx test dms-material` immediately after this story (new red-phase tests skipped), and Story 4.2's first task is to remove the `.skip()` markers, confirm they FAIL against current code, then implement the fix until they pass.

## Dev Notes

- **Root cause (verified against installed smart-core):** SmartNgRX's `BaseArrayProxy.addToStore()` (`node_modules/@smarttools/smart-core/fesm2022/smarttools-smart-core.mjs`, ~line 2141) builds the new parent virtual-array object as `{ indexes, length }` ONLY — it does NOT copy `startIndex`. It then calls `parentService.loadByIdsSuccess([newParent])`. The store's merge path (`mergeVirtualArrays`, ~line 162; `mergeNewRowWithExisting`, ~line 205) preserves the existing virtual-array contents, but the reconstructed parent object written by `addToStore` is missing `startIndex`, so after reconciliation the stored `Account.openTrades` / `Account.divDeposits` can end up with `startIndex === undefined`. Any subsequent read of the virtual array that depends on `startIndex` (e.g. re-evaluating a computed signal on route change) throws — this is the navigation crash Dave reports.
- **The two add call sites** both go through `SmartArray.add()` → `addToStore()`:
  - `apps/dms-material/src/app/account-panel/open-positions/add-position.service.ts:114` — `tradesArray.add!(tradeData, currentAccount())`.
  - `apps/dms-material/src/app/account-panel/dividend-deposits/dividend-deposits-component.service.ts:117` — `divDepositsArray.add!(...)`.
- **The virtual-array shape** is `{ startIndex: number; indexes: string[]; length: number }` (see `Account.openTrades` / `soldTrades` / `divDeposits` in `apps/dms-material/src/app/store/accounts/account.interface.ts`, typed `PartialArrayDefinition | SmartArray<Account, T>`). The default row factory (`accounts-definition.const.ts`) seeds all three as `{ startIndex: 0, indexes: [], length: 0 }`.
- **How to read the parent state in a unit test:** the services already inject the relevant signal store and expose computed signals. For add-position, `AddPositionService` uses `currentAccountSignalStore` + `selectCurrentAccountSignal`; for div-deposits, `DividendDepositsComponentService` does the same. In the spec, drive the dialog result / payload through the existing service method, then read the account signal and inspect `.openTrades` / `.divDeposits`. If the store accessor returns a proxy, use its `.toJSON()` or index access to materialize `indexes`/`length`; assert on the raw virtual-array fields.
- **Red-phase TDD:** this story is ordered before Story 4.2. The state-integrity assertions (AC #1–#3) are marked `it.skip` so CI stays green while the bug still exists; Story 4.2's first task removes the skip markers, confirms red, then fixes until green.
- **Do NOT modify production code in this story** — unit-test scaffold only. The fix belongs to Story 4.2.
- Vitest is the workspace test framework; dms-material unit tests run via `nx test dms-material`.
