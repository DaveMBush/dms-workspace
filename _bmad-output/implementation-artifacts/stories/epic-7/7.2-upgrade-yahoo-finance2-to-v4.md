# Story 7.2: Upgrade yahoo-finance2 to v4

Status: in-progress

## Story

As a user (Dave),
I want the `yahoo-finance2` package upgraded from the v3 line to version 4.0.4, with any resulting API breakage fixed at the single import point and consumer tests insulated from the package internals,
So that the server runs on the current major release of the library.

## Acceptance Criteria

1. The declared `yahoo-finance2` version in the root `package.json` is updated to target 4.0.4 (e.g., `"^4.0.4"`), and `pnpm install` updates `pnpm-lock.yaml` so the resolved version is on the v4 line.
2. The single raw-package import point, `apps/server/src/app/routes/settings/yahoo-finance.instance.ts`, still constructs and exports a working `yahooFinance` instance after the bump — any v3→v4 constructor or option changes are handled here (or at the call sites) so all three consumers keep working.
3. All three consumer call sites (`symbol/search/index.ts` → `search()`, `import/resolve-cusip.function.ts` → `search()`, `settings/common/get-last-price.function.ts` → `quote()`) still compile and pass their existing unit tests after the upgrade; any v4 signature changes are fixed at these call sites or the instance module, not by weakening the tests.
4. Story 7.1's red-phase tests are unskipped and pass under the server test runner (version assertion now green); no pre-existing server test regresses, and `nx run dms-server:lint` + build introduce no new errors.

## Dev Notes

- Red-phase TDD convention: Story 7.1 wrote failing tests marked `.skip()` so CI stayed green; this story's FIRST task is to remove those skips, confirm they fail (red), then bump the package and fix breakage until green. Both stories are `Status: ready-for-dev`.
- **Current state verified on disk:** `yahoo-finance2` is declared in the ROOT `package.json` line 69 as `"^3.13.0"` (resolved to `3.15.4` in `pnpm-lock.yaml`) — it is NOT a key in `apps/server/package.json`. The bump therefore edits the root manifest, not the server's.
- **Single import point:** only `settings/yahoo-finance.instance.ts` (line 2) imports the raw package and re-exports the `yahooFinance` instance; all three consumers call that instance, never the package directly. Prefer fixing v4 breakage at this one module so consumers stay untouched where possible — this is exactly why Story 7.1's AC #2 locks in "mock the instance module" as the test contract (tests must not import the raw package).
- **Do NOT couple tests to package internals:** the existing consumer specs (`resolve-cusip.function.spec.ts`, `get-last-price.function.spec.ts`) already mock the instance module — keep it that way. If a v4 change forces a spec edit, edit the mocked method's signature/return shape, not an import of `yahoo-finance2`.
- **Prose note:** the epic prose says this "will need to be done in one story," but the validator forbids a single-story epic (count must satisfy both `% 2` and `% 3`). This is therefore the minimal valid pair: a red-phase contract + its implementation, with no e2e story.
